# Measure outflow, not inflow

**Claim.** "Is this system alive / healthy / working?" is answered by what *leaves* it — merges, releases, responses, completed runs — never by what *enters* it. Queues measure demand and noise; drains measure function. Any activity metric built on inflow counts the arrivals of a system that may have stopped processing years ago.

**Why.** Inflow is cheap to produce and hard to stop: anyone can open a PR, file an issue, submit a form, enqueue a job. Outflow requires a functioning processor: a maintainer who merges, a CI that releases, a worker that drains. A system whose processor died keeps accumulating inflow — the pile grows *because* nothing works, which inverts the signal: the healthier the queue looks, the deader the system.

**Failure example.** A curated list carried eight open pull requests and a detailed contribution guide; both read as "active community". The last *merged* PR was over a year old. The eight PRs were not a queue being worked — they were the sediment of a drain that had closed. A contribution formatted to the letter of the rules was opened against it and withdrawn the same day. (Recorded in full in [retractions 008](https://github.com/Orvii/retractions/blob/main/entries/008-open-prs-are-not-a-community.md).) The same inversion appears in ops: a job queue with 10k pending items and zero completions is not "busy", it is stopped; a support inbox with 400 unread tickets is not "popular", it is unstaffed.

**Method.** For any liveness or throughput claim, report the outflow rate over a window and the age of the oldest unprocessed item: merged PRs per month, releases per quarter, completions per minute, median time-to-first-response. Then compare against inflow: a stable queue with real outflow is healthy; a growing queue with no outflow is a corpse with good marketing. In benchmarks the same rule reads: report completed runs and their distribution, not submitted jobs; a harness that enqueues 10k cases and finishes 40 has measured nothing.

**Counter-note.** Inflow is not useless — it is the *demand* signal, and the ratio outflow/inflow is a genuine load metric (drain rate, backlog turnover). The error is using inflow alone as a health proxy. A repo with many open PRs *and* weekly merges is a busy community; the same pile with no merges is a memorial. Count what left the system; use what entered only as the denominator.
